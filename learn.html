Chapter 01 · Mental model

The internet is a delivery system.

Think of it as a worldwide postal service for tiny pieces of data. It does not move one giant message in a straight line. It divides the message, labels the pieces, and lets many networks cooperate to deliver them.

✉

Your message

A web request, video call, photo, or game action.

▤

Packets

Numbered envelopes that carry small portions of the data.

⌁

Routers

Sorting offices that choose where each packet goes next.

◎

Server

A computer that receives the request and prepares an answer.

Remember this

The internet is a network of networks. No single company owns all of it, and packets do not need to take the same route.

Chapter 02 · The physical world

Every cute emoji becomes numbers.

Computers store information as bits: values that can be 0 or 1. Encoding rules such as UTF‑8 turn letters and emoji into bytes. Network hardware then represents those bits using radio waves, electrical voltage, or flashes of light.

Chapter 03 · Before the internet

Your packet’s first trip is across the room.

Your device joins a local network using Wi‑Fi or Ethernet. DHCP usually gives it a private IP address, subnet details, a DNS resolver, and the address of a default gateway—your router.

Home routerPublic IP 203.0.113.8
NAT translation192.168.1.12:53142→203.0.113.8:62001

The router remembers that replies to port 62001 belong to the laptop.

What are MAC, ARP, DHCP, and NAT?
MAC address
A local identifier for a network interface. It helps deliver a frame on the current link, not across the whole internet.
ARP
IPv4’s “who has this local IP?” question. It discovers the MAC address of the next local device, often the router.
DHCP
The automatic welcome desk that gives a joining device its network settings.
NAT
A router’s translation table that lets many private devices share one public IPv4 address.

Chapter 05 · Reliable delivery

Packets can arrive late, twice, or not at all.

IP makes a best effort but promises neither delivery nor order. TCP adds sequence numbers and acknowledgements. UDP is simpler and faster when an application can tolerate loss or provide its own reliability. QUIC builds secure, reliable streams over UDP.

Chapter 06 · Choosing a path

A router answers one question: “where next?”

It reads the destination IP, checks a routing table, and forwards the packet to a next hop. Inside an ISP, routing protocols find paths. Between independent networks, BGP advertises which network can reach which IP prefixes.

Interactive · physics of latency

Distance sets a speed limit

Physics-only minimum RTT50 ms

This is only travel time there and back. Routers, queues, Wi‑Fi, processing, and a longer real cable route add more delay.

Hop count

Number of forwarding steps seen by traceroute—not a measure of kilometres.

RTT

Time for a probe and reply. It includes both directions and processing.

Mapped distance

Great-circle distance between approximate visible locations. It is not the exact cable length.

Chapter 08 · Trust on an untrusted network

HTTPS makes a protected tunnel.

TLS authenticates the website, agrees on temporary encryption keys, then protects confidentiality and integrity. People carrying packets can still see some metadata—such as IP addresses and timing—but not the encrypted page contents.

  1. 1Client helloYour browser proposes TLS versions and cryptographic options.
  2. 2Server certificateThe site proves control of a name using a certificate signed by a trusted authority.
  3. 3Key agreementBoth sides independently derive shared session keys; the key itself is not sent as plain text.
  4. 4Encrypted recordsAuthenticated encryption hides content and detects changes.

Encryption is not the same as anonymity.

TLS protects what you say. It does not automatically hide which IP address you contacted, packet sizes, or timing. A VPN changes who sees different parts of that metadata, but it shifts trust to the VPN provider.

Chapter 10 · The machines and cables

The cloud is somebody else’s building.

Data centers contain racks of computers, switches, storage, cooling, batteries, generators, and multiple network links. CDNs place copies of content in many regions so users can often reach a nearby edge instead of one distant origin.

CDN edge

A nearby copy

Cached images, scripts, and sometimes complete pages can be served closer to the user.

Load balancer

A traffic coordinator

It distributes requests across healthy servers so one machine is not overwhelmed.

Origin server

The source of truth

It runs application logic and provides content when an edge does not have a fresh copy.

Important limitation

Traceroute cannot tell you the exact undersea cable. A map can match known landing points and geography, but without operator telemetry the cable choice remains an inference.

Chapter 11 · Investigate it yourself

Three tools answer three different questions.

Networking becomes much easier when you choose a tool based on the question—not when you run every command and hope.

nslookup example.com

What IP did DNS return?

Use dig or nslookup to inspect name records and their TTL.

ping example.com

Can probes return, and how long?

Ping measures ICMP round-trip time when the destination allows it. A blocked ping does not prove a website is down.

traceroute example.com

Which routers answered along the way?

Traceroute varies the hop limit. Silent routers and asymmetric return routes make it an incomplete observation.

Open the plain-English glossary
Bandwidth
How much data a link can carry per second. A wider pipe, not necessarily a faster first drop.
Latency
The delay before data reaches its destination. Distance, queues, and processing all contribute.
Packet loss
Data that never arrives. Reliable transports retransmit it; real-time apps may continue without it.
Port
A number that identifies a network conversation or service on a device, such as HTTPS on 443.
Firewall
A rule system that allows or blocks traffic based on addresses, ports, protocol, and state.
ISP
The organization that connects your home, phone, school, or company to other networks.
IXP
A facility where independent networks connect and exchange traffic directly.
Cache
A nearby temporary copy that avoids repeating slow or expensive work.
